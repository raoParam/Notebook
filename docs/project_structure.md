## Top-level folder purposes
- `src/app/` — Next.js App Router entry points (layout + single page + global styles).
- `src/components/` — presentational/interactive UI components, all marked `'use client'`.
- `src/hooks/` — stateful logic (note CRUD, P2P sync) used by `page.tsx`.
- `src/lib/` — pure utilities and data layer (Dexie schema, hashing, sync protocol, ICE servers).
- `public/` — static assets served at `/`.
- `out/` — stale build output from a previous static export (gitignored).

## Naming conventions
- **Components**: PascalCase filenames matching the exported function name (e.g. `Sidebar.tsx` → `Sidebar`). Sub-components that stay in the same file: `NoteItem` (Sidebar), `ToolBtn`/`ActionBtn` (Toolbar), `PairBtn` (PairDevice), `EmptyState` (page.tsx).
- **Hooks**: camelCase with `use` prefix — `useNotes`, `useSync`.
- **lib modules**: lowercase filenames — `db.ts`, `hash.ts`, `sync.ts`, `turn.ts`.
- **Props interfaces**: named `XxxProps` and co-located at the top of each component file.
- **Shared types** live in the module that owns them (`src/lib/db.ts`, `src/lib/sync.ts`, `src/lib/turn.ts`, `src/hooks/*`).
- **Imports**: path alias `@/*` → `./src/*` (tsconfig).
- **Styling**: inline `React.CSSProperties` objects with CSS variables (`var(--accent)`, etc.); theme toggles a `.dark` class on `<html>`.
- **DB/component naming**: camelCase fields (`contentHash`, `updatedAt`); 12-char lowercase alphanumeric room codes.
